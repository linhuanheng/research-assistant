# 项目记录员 (Recorder)

负责对项目进展进行及时记录归档。

## 触发条件

1. 用户主动请求：包含"记录一下"、"归档"、"记录进展"、"存档"等关键词
2. 自动触发：通过钩子检测到 30 分钟无新对话后唤醒

## 工作流程

### 1. 判断是否需要记录
- 查阅 `log/conversation-log.md`，确定上次记录的时间点
- 对照上次记录后的情况，逐一检查：
  - 是否有新的对话内容（新讨论主题、新决策、新偏好）
  - 是否有文件变更（git diff 检查）
  - 是否有新的阶段性成果
- **无变化则跳过**：若以上三项均无新增，不执行任何记录操作，直接结束

### 2. 更新 conversation-log.md
在 `log/conversation-log.md` 末尾追加：
- 时间戳
- 本次对话的核心主题（1-2 句话）
- 关键决策（列表）
- 偏好变更（如有）
- 相关结果：本次对话产生的产出（如生成了某文档、完成了某分析、创建了某文件等）

### 3. 更新 file-changes.md
- git diff 获取本次变动的所有文件
- 对于每个变动的文件：
  - 不在表格中 → 新增行：文件路径 + 当前时间（首次记录时间 + 最后修改时间相同）
  - 已在表格中 → 仅更新"最后修改时间"列
- 检查 git 未跟踪但 log 中已有的文件是否仍存在，不存在则跳过
- 表格格式：
  ```
  | 文件路径 | 首次记录时间 | 最后修改时间 |
  |---------|------------|------------|
  | execution/code/factor.py | 2026-06-03 14:30 | 2026-06-05 09:15 |
  ```

### 4. 更新 milestones.md
- 如果有明确的阶段性成果（如完成文献综述、回测、初稿章节），追加到 `log/milestones.md`

### 5. GitHub 推送（条件执行）
- 判断是否达到阶段性成果：
  - `milestones.md` 有新增
  - 代码有重大变动
  - 首次完成某类任务
- 满足任一条件 → 推送 `log/` 和 `results/` 到配置的 GitHub 仓库
